# Map Screen Fog of War

> A single PNG mask painted by the DM over the active battlemap: black hides, transparent reveals. Edited in a dedicated modal (brush / rectangle / grid-cell / room-reveal, reveal or cover), rendered on the map screen inside the stage transform, and persisted per map as a vault sidecar PNG keyed by the map's `/vault/` URL — note images and Hydrus-cached files alike. A companion Walls editor in the same modal defines line segments that block line-of-sight; walls are persisted as a JSON sidecar and broadcast as `map-walls` so vision holes are clipped to LoS on the client. The Walls tab supports importing walls from a UVTT file (`.dd2vtt`, `.uvtt`, `.df2vtt`, `.json`) or from a Foundry module `.zip` (Czepeku/Foundry format). A Rect wall tool lets the DM drag a rectangle that becomes four independent wall segments.

## Settings used

- `mapFogTvOpacity` — fog opacity on the map screen (default 1); changing it re-broadcasts fog through the open DM panel

## Requirements

1. While a map is active, the Map Screen section shall render a Fog button that opens `MapFogModal`; the label reads `Fog ●` when the map has fog and `Fog` otherwise.
2. The fog mask shall be an offscreen canvas of width `1024` (`FOG_RESOLUTION`) and height `max(1, round(1024 × naturalHeight/naturalWidth))`; black = hidden, transparent = revealed. A map with no stored fog starts fully transparent.
3. The modal shall expose two tabs (`dm-fog-tabs`): **Fog** and **Walls**. Switching tabs rebuilds the toolbar and reattaches drawing listeners; the stage and overlay are shared.
4. The Fog tab shall offer Reveal/Cover modes × Brush (stamped circles sized by a 2–15% slider), Rectangle (dashed marquee — `#7bd88f` reveal / `#f97583` cover — committed on mouseup), Grid cell (whole cells snapped via `gridCellRectAt`), Grid rect (same dashed marquee as Rectangle but the committed rect is snapped to whole grid cells), and Room tools, plus Reveal All and Cover All. Reveal composites with `destination-out`; Cover paints opaque black with `source-over`. The mask renders at 0.55 alpha in Fog mode (0.25 in Walls mode) so the DM sees the map beneath.
5. The Room tool (Fog tab) shall: (a) build the `blocked` mask via `buildBlockedMask(walls, fw, fh, fogScale, pxPerSquare, blocksSight)` — which rasterizes the admitted (sight-blocking) walls at fog resolution, reads `getImageData`, and seals the mask's 1px outer border (the map edge acts as a wall, mirroring how `visibilityPolygon` closes with the bounds rect) — then call `floodRegion(blocked, fw, fh, fx, fy)`; (b) if `floodRegion` returns null show `new Notice("That point is inside a wall")` and return; (c) otherwise paint the region — via `regionToCanvas(region, fw, fh)` — onto the fog canvas via `applyMode` + `drawImage`, call `redraw()` and `commit()`.
6. When a stroke completes (mouseup), when Reveal All / Cover All is clicked, or when the Room tool fires, the modal shall call `commitFog`, which re-encodes the mask as a PNG data URL, writes the sidecar, and broadcasts `map-fog { dataUrl, opacity: mapFogTvOpacity }`.
7. The sidecar shall live at `.dm-screen/fog/<tail>-<fnv1a(mapUrl)>.png`, where `<tail>` is the sanitized last 60 characters of the decoded vault path (fallback `x` when sanitization strips everything) — deterministic per map URL, identical for note-image and Hydrus-cached maps.
8. When a map is applied, `setVaultMap` shall load the fog sidecar into `fogDataUrl` (or null) and the walls sidecar into `walls`, then broadcast `map-fog` and `map-walls` alongside the other map messages.
9. When the map client receives `map-fog` with a data URL, it shall validate it with `safePlayerUrl(url, "image")` and composite into `#map-fog`: draw the fog image at natural size, then erase each active vision shape via `eraseVisionWithWalls`. Canvas display is set to `block` at the payload opacity; `dataUrl: null` clears and hides the canvas. Rejected URLs are logged via `console.warn` and skipped.
10. `eraseVisionWithWalls(ctx, vision, scale, pxPerSquare, walls, mapWidth, mapHeight)` shall: if no wall `blocksSight`, fall through to `eraseVision`; otherwise compute `visibilityPolygon` from the vision centre, clip the canvas to the polygon path, then call `eraseVision` inside the clip; skip when the polygon has fewer than 3 points.
11. When the map client receives `map-vision` with a `visions` array, it shall store the list and recomposite the fog canvas immediately (no-op when no fog image is loaded).
12. When the map client receives `map-walls` with a `walls` array, it shall store the list and recomposite the fog canvas immediately.
13. `map-clear` shall clear and hide the fog canvas and reset visions and walls on the client; `stopMap` resets `fogDataUrl` and `walls` to null/empty — sidecars are never deleted, so re-adding the same map restores them.
14. `restoreFromCache` shall recover `fogDataUrl` from the `map-fog` slot and `walls` from the `map-walls` slot; `republish()` shall re-broadcast `map-fog` and `map-walls` while a map is active.
15. When `mapFogTvOpacity` changes in settings, the plugin shall re-broadcast fog through the open DM Control Panel so connected screens update live.
16. When the modal closes during an in-progress drag, the document-level mousemove/mouseup listeners shall be removed (`cleanupDrag`).
17. The overlay shall draw all walls scaled by `fogScale`: plain walls `#f5d90a` lineWidth 3; door walls `#44aaff`; open doors dashed (`setLineDash([8,6])`). In Walls mode, if a chain draft is active, a dashed preview segment shall be drawn from the anchor to the current cursor.
18. The Walls tab shall offer Wall, Door, Erase, Toggle door, and Rect tools, plus a Snap checkbox.
19. Wall and Door tools shall use chained left-click drawing: the first click sets the anchor; each subsequent click appends a segment from the anchor to the clicked point (snapped to grid intersections when Snap is checked, ignored when zero-length) and advances the anchor; right-click (contextmenu, preventDefault) ends the chain without adding a segment.
19a. The Rect tool shall use a drag gesture: mousedown records the natural-coord anchor (snapped if Snap is checked); mousemove draws a dashed `#f5d90a` rectangle preview on the overlay; mouseup computes the axis-aligned bbox (min/max of the two natural corners, snapped if Snap on), discards degenerate rects (zero width or height), and appends four independent plain walls (top, right, bottom, left) to `this.walls`, then calls `commitWalls`. Document-level mousemove/mouseup listeners are registered on mousedown and cleaned up in `cleanupDrag`.
20. The Erase tool shall remove the nearest wall whose point-to-segment distance (in natural coords) is less than `12 / fogScale`; Toggle door shall flip `open` on the nearest door wall within the same hit radius. Both commit immediately via `panel.commitWalls`.
21. `broadcastWalls()` shall broadcast `{ type: "map-walls", payload: { walls } }`; `commitWalls(walls)` shall update `this.walls`, write the walls sidecar (at `wallsSidecarPath`), and call `broadcastWalls()`; `republish()` shall call `broadcastWalls()` alongside `broadcastFog()` — an empty walls list is a valid signal for late joiners.

## UVTT import

28. The Walls tab toolbar shall include an **Import UVTT** button. Accepted file types: `.dd2vtt`, `.uvtt`, `.df2vtt`, `.json`. On click the button opens a native file picker; on file selection the file is read as text and JSON-parsed.
29. `parseUvttWalls(doc: unknown): UvttParseResult` (in `src/map/uvtt.ts`) shall validate the document at the boundary: `resolution.map_size.x/y` must be finite positive numbers; `resolution.pixels_per_grid` must be a finite positive number; missing fields throw `new Error("Not a UVTT file (missing resolution/pixels_per_grid)")`. `line_of_sight`, `objects_line_of_sight`, and `portals` default to `[]` when absent.
30. `parseUvttWalls` shall convert polylines: every consecutive pair of points in `line_of_sight` and then `objects_line_of_sight` → `{ x1, y1, x2, y2 }` where each coordinate is `(point.coord − map_origin.coord) × pixels_per_grid`. Zero-length segments and polylines with fewer than 2 points are skipped. Portals with ≥ 2 bounds points → `{ x1: first.x, y1: first.y, x2: last.x, y2: last.y, door: true }` (same coordinate transform); `open: true` is added when `portal.closed === false`. Result order: `line_of_sight` segments, then `objects_line_of_sight` segments, then portal walls.
31. On any parse error, `importUvttDoc` shall show `new Notice(\`UVTT import failed: ${message}\`, 6000)` and return without modifying walls.
32. On success, the parsed walls shall be scaled to the displayed map via `applyImportedWalls(result, sourceLabel)`: `scale = this.map.naturalWidth / (result.gridSquares.x × result.pixelsPerGrid)`. Every wall coordinate is multiplied by `scale`. `this.walls` is replaced with the scaled list, `panel.commitWalls([...this.walls])` is called, and the overlay is redrawn.
33. On success, the map grid shall be configured via `panel.applyGridConfig(pxPerSquare, 0, 0)` where `pxPerSquare = this.map.naturalWidth / result.gridSquares.x` (integer when the division is exact, otherwise rounded to 2 decimal places). `applyGridConfig` sets `state.pxPerSquare / gridOffsetX / gridOffsetY`, calls `broadcastConfig()`, `persistState()`, and `host.render()`.
34. On success, the modal shall show `new Notice(\`Imported ${walls.length} walls (${doors} doors) — grid set to ${pxPerSquare} px/square\`)` where `doors` is the count of walls with `door: true`.

## Foundry module import

35. The Walls tab toolbar shall include an **Import Foundry** button. Accepted file type: `.zip`. On click the button opens a native file picker; on file selection the file is read as `ArrayBuffer`, converted to `Uint8Array`, and passed to `importFoundryZip`.
36. `importFoundryZip(zipBytes: Uint8Array)` shall: unzip via `unzipSync` (fflate) with a filter that admits only `.db`, `.log`, `.ldb` entries (large image assets are NOT inflated); pass the resulting entry map to `parseFoundryModule`; on any error (bad zip or no scene) show `new Notice(\`Foundry import failed: ${message}\`, 6000)` and return; on success call `applyImportedWalls(result, "importFoundryZip")`.
37. `parseFoundryModule(entries: Record<string, Uint8Array>): FoundryImportResult` (in `src/map/foundry.ts`) shall: gather scene documents from every `.db` entry via `parseNedb` (TextDecoder, walls inline); gather scene documents from every `.log`/`.ldb` entry under a `packs` path via `parseLeveldbEntries` + the embedded-collection assembly (requirement 39a); call `pickScene`; throw `new Error("No scene with walls found in module")` when no scene is found; return `{ walls: scene.walls (in scene px), gridSquares: { x: width/gridSize, y: height/gridSize }, pixelsPerGrid: gridSize }`.
38. `parseNedb(text: string): unknown[]` shall split on newlines, `JSON.parse` each non-empty line, ignore parse failures, and skip docs that carry a `$$deleted` key.
39. `parseLeveldbEntries(bytes: Uint8Array): LeveldbEntry[]` shall parse the LevelDB write-ahead-log: 32768-byte blocks; each record header is `crc(4 LE) + length(2 LE) + type(1)` (CRC is not verified); types 1=FULL (emit immediately), 2=FIRST / 3=MIDDLE / 4=LAST (concatenate, then emit); stop a block when a zero-length/zero-type header appears; for each reassembled record, locate the first `{`, parse the balanced top-level JSON object via brace-depth walking (respecting strings and escapes), and recover the document's LevelDB key from the record bytes preceding the value (`!scenes!<id>` or `!scenes.walls!<sceneId>.<wallId>`). `parseLeveldbLog` is `parseLeveldbEntries(...).map(e => e.doc)`.
39a. The LevelDB embedded-collection assembly shall group `!scenes.walls!<sceneId>.<wallId>` documents by their key's `sceneId` and, for each scene document that lacks inline wall geometry (its `walls` array holds ID strings, not objects with `c`), replace `walls` with the wall documents grouped under the scene's `_id` — yielding scene docs in the inline shape `foundrySceneToWalls` consumes.
40. `foundrySceneToWalls(scene): FoundryScene | null` shall: require numeric `width`, `height`, array `walls`, and `grid` that is either a number or `{ size: number }`; subtract the padded-scene inset from every wall coordinate — `padX = ceil(width × padding / gridSize) × gridSize`, `padY` likewise (Foundry stores `padding` explicitly, default 0.25; an absent field is treated as 0 so non-Foundry callers are not shifted) — so walls land relative to the background image's top-left; filter walls that do not block sight (`sense === 0` in older Foundry, `sight === 0` in newer); skip zero-length walls (`x1===x2 && y1===y2`); for `door > 0` produce `{ x1,y1,x2,y2,door:true, ...(ds===1 ? {open:true} : {}) }`; return null when no valid walls or invalid dims.
41. `pickScene(docs): FoundryScene | null` shall: keep docs accepted by `foundrySceneToWalls`; prefer scenes whose `name` has no `(` (base variant); among ties pick the one with the most walls; return null when no scene is found.

## DM vision controls

The Map Screen section exposes a Vision subsystem below AoE Overlays while a map is active.

22. The DM panel shall render a Vision section (via the reusable `renderVisionSection(container, map, onChange)`, shared with the Explore modal's side panel) with an Add Vision menu (Circle 30 ft / Square 30 ft); new visions spawn at the map center with `sizeFt: 30` and `featherFt: 5`. `MapVision` carries an optional `followsView` flag.
23. When visions exist the section shall also render a Bake into fog button and a Clear All button; Bake composites all active visions onto the persistent fog mask (building a canvas, drawing the existing fog if present, erasing each vision with `eraseVisionWithWalls` using the current `walls`, then calling `commitFog`) and clears the live vision list; Clear All empties the list and broadcasts immediately.
24. Each vision row shall expose: shape select (circle / square), sizeFt number input (min 5 step 5, title "Vision range (ft)"), featherFt number input (min 0 step 5, title "Feather (ft)"), a bind-to-view toggle button (`.dm-map-vision-bind`, glyph `⦿`, `dm-fog-active` when bound), and a remove ✕ button; each change broadcasts `map-vision` immediately.
24a. The bind-to-view toggle shall flip `vision.followsView`; when turning it on it snaps the vision centre to the current `state.panX/panY`. `syncBoundVisions(immediate?)` moves every `followsView` vision's `x/y` onto `state.panX/panY`, broadcasts when any moved, and returns whether any moved; it is called from `applyExplorePan` and from the pan-preview `applyPan` so a bound vision's lit area tracks whatever the players currently see.
25. Each vision shall carry a draggable dot (`.dm-map-vision-dot`) in the pan preview positioned at `(x/nw, y/nh)` percent; left-drag moves the vision (same `deltaToMap` + clamp pattern as AoE dots), throttled broadcast during drag, immediate on mouseup. When `applyPan` reports a bound vision moved (`syncBoundVisions()` returned true), the preview shall both `redrawAoes()` (the dashed outline) and re-run each vision dot's positioner, so the `.dm-map-vision-dot` marker follows the viewport — not just the canvas outline.
26. The `redrawAoes` canvas shall also draw a dashed `#ffd23f` 2px outline for each vision: arc for circle, rect for square, at `sizeFt * (pxPerSquare/5) * s` radius/half-side.
27. `broadcastVisions(immediate?)` shall follow the same throttle pattern as `broadcastAoes`; `setVaultMap` resets `this.visions = []` and calls `broadcastVisions(true)`; `stopMap` resets `this.visions`; `restoreFromCache` recovers from the `map-vision` slot; `republish()` re-broadcasts visions when non-empty.

## Exploration Mode

A dedicated table-play surface, separate from the Fog editor: no drawing toolbar. Left-click on the map alternates two gestures (toggle a door, reveal/cover a room); a right-hand control panel reuses the DM panel's AoE and Vision sections in full. On top of that the DM can drag the players' viewport window (physical mode, unless the view is locked) and move the AoE and vision markers. Holding Shift momentarily focuses the door/room gestures by letting clicks pass through every marker. Doors, fog, AoE, vision, and view moves all broadcast through the existing `commitWalls` / `commitFog` / `broadcastAoes` / `broadcastVisions` / `applyExplorePan` methods — no new message types.

42. While a map is active, the Map Screen section shall render an **Explore** button (in the same button row as the Fog button, after it) that opens `MapExploreModal`; the modal class is `dm-explore-modal`, sized ~96vw × 96vh.
43. `MapExploreModal(app, plugin, panel, map)` shall lay out (inside the `dm-explore-content` wrapper on `contentEl`) a `dm-explore-bar` (top) over a `dm-explore-body` row that holds the map `dm-explore-stage` (grows) and a fixed-width `dm-explore-sidebar` (right). The stage shows the map media (image via `getResourcePath`, video autoplay/muted/loop) inside a `dm-explore-inner` box that carries the map's aspect ratio, is centred, and is rotated by the map's configured `panel.state.rotation` (0/90/180/270) via a CSS `rotate()` transform (sized so the rotated box fits the stage). It shall load `panel.fogDataUrl` into a 1024-wide fog canvas the same way `buildFogCanvas` does, overlay a `dm-explore-overlay` canvas at fog resolution, and add a pointer-transparent `dm-explore-markers` layer above it (only dots and the viewport rect capture pointer events). The overlay draws the current fog at 0.5 alpha, then the hover highlight, then each panel AoE via `renderAoe(octx, aoe, fogScale, 0, 0, pxPerSquare, 0)`, then vision range outlines (dashed `#ffd23f`, radius `sizeFt × (pxPerSquare/5) × fogScale`), then walls faintly (0.35 alpha; plain `#f5d90a`, doors `#44aaff`), then door markers.
43a. The sidebar shall render the AoE and Vision controls by calling `panel.renderAoeSection(sidebar, map, refresh)` and `panel.renderVisionSection(sidebar, map, refresh)` — the same full row controls as the DM panel (add/clear, shape, size, colour, opacity, rotation, feather, bind-to-view, remove). The `refresh` callback rebuilds the sidebar, re-renders the on-map markers, and repaints the overlay, so an edit made in the panel is reflected on the map immediately.
44. Each door shall draw a filled circle marker at its segment midpoint — `#7bd88f` when open, `#888888` when closed — of radius `max(10, pxPerSquare × fogScale × 0.35)`. `fogScale = fogCanvas.width / map.naturalWidth`.
45. Overlay client coordinates shall be converted to fog/map space through the map rotation: `toFog`/`deltaToMap` read the overlay's own bounding rect (centre + rotation-unrotated dimensions) and apply `rotatePoint(..., (360 − rotation) % 360)`, so hit-testing and marker drags stay correct under a rotated view.
46. A left mousedown on the overlay shall first hit-test doors: the nearest door whose midpoint (natural coords) is within `(doorRadius + 6) / fogScale` of the click toggles its `open` via an immutable update (`this.walls.map(w => w === hit ? { ...w, open: !w.open } : w)`) and calls `panel.commitWalls([...])`; the original wall object is not mutated. A door hit consumes the click (no fog toggle).
47. When no door is hit, the click shall auto-toggle the clicked room's fog: sample the fog canvas alpha at the clicked fog pixel — if revealed (`alpha < 128`) paint the room region opaque black (`source-over`), otherwise erase it to transparent (`destination-out`) — then call `panel.commitFog(fogCanvas.toDataURL("image/png"))`.
48. The room region shall be computed by `computeRegion(fx, fy, fogScale)`: flood the memoized all-walls blocked mask via `floodRegion`. The mask is built by `buildBlockedMask(walls, fw, fh, fogScale, pxPerSquare, () => true)` — rasterizing **all** walls (doors included, regardless of `open`) as blocking lines and sealing the 1px border — and cached against the current `walls` reference + `fogScale`, so hover and click reuse one rasterization until the walls list changes (a door toggle drops the cache). Doors are ALWAYS room boundaries in exploration (this differs from the Fog Room tool of req 5, which admits only `blocksSight` walls); open/closed affects only the player-TV LoS via the `map-walls` broadcast. When `floodRegion` returns null (a wall pixel) show `new Notice("That point is inside a wall")` and do nothing.
49. On mousemove over the overlay, when the hovered fog cell changes, the modal shall recompute that cell's region and draw a subtle green highlight (`rgba(123,216,143,0.25)`) on the overlay so the DM sees which room will toggle; mouseleave clears the highlight. The hovered cell's region is memoized (keyed by the floored fog cell) so the subsequent click reuses it when it lands in the same cell, and the tint is produced by filling the `regionToCanvas` mask with the highlight colour via `source-in`.
50. The top bar (`dm-explore-bar`) shall offer **Reveal All** (clear the fog canvas), **Cover All** (fill it opaque black), a **lock** button (`dm-explore-lock-btn`, lucide `lock`/`unlock`, `dm-fog-active` when locked), and **Exit** (close the modal). Reveal All and Cover All commit fog like the Fog editor's equivalents. The lock button toggles `panel.viewLocked` (a getter/setter over the shared `previewLocked`) and re-renders the markers.
51. In physical mode the markers layer shall render a players'-viewport rectangle (`dm-map-viewport-rect`), sized and positioned from `panel.playerViewportMapSize()` and `panel.state.panX/panY`. When `panel.viewLocked` is true the rectangle is a passive dashed outline (`dm-explore-rect-locked`, no pointer events) and cannot be dragged. Otherwise dragging it calls `panel.applyExplorePan(panX, panY, false)` (throttled) during the drag and `panel.applyExplorePan(panX, panY, true)` on release, moving only the players' TV window (the DM's own rotated view is untouched). No rectangle is shown in fit mode.
51a. `applyExplorePan` calls `syncBoundVisions`, so any vision with `followsView` moves onto the new view centre as the rectangle drags; when at least one bound vision exists the drag also repaints the overlay and re-renders the markers each step, so the lit area and its dot track the viewport live.
52. The markers layer shall render each panel AoE as a draggable anchor dot (`dm-map-aoe-dot`) — and, for non-symmetric shapes, a rotation handle (`dm-map-aoe-rot-handle`) at the shape's tip/mid-edge — mirroring the panel pan-preview: dragging moves/rotates the AoE (`panel.broadcastAoes()` throttled, `panel.broadcastAoes(true)` on release); right-click (contextmenu, preventDefault) removes it via `panel.removeAoe(id)` and re-renders. Each panel vision renders a draggable dot (`dm-map-vision-dot`) that moves the vision (`panel.broadcastVisions()` / `broadcastVisions(true)` on release). Numeric editing (add, remove, size, feather, colour, bind) happens in the sidebar (requirement 43a); the on-map dots only reposition.
52a. While Shift is held, the markers layer shall carry `dm-explore-focus`, which sets `pointer-events: none` on the layer and all its children, so left-clicks pass through the viewport rect and every AoE/vision dot to the overlay's door/room gestures — a momentary focus that needs no view lock. The class is added on a `Shift` `keydown` (document), removed on its `keyup`, and reset on `window` `blur` (so Shift held during an alt-tab does not stick).
53. On close the modal shall force-detach any in-progress document drag (`activeDrag`), remove its overlay-level mousedown/mousemove/mouseleave listeners and the document `keydown`/`keyup` + window `blur` Shift-focus listeners (`cleanupListeners`), call `panel.refreshPanel()` so the DM panel re-renders with the mutated AoE/vision/pan state, and empty `contentEl`.

## Non-goals

- Fog on the player screen at `/` (it has its own per-layer fog, `../fog-of-war/overview.md`).
- Line-of-sight computation inside the Exploration modal. Toggling a door commits walls; the player TV recomputes LoS from the `map-walls` broadcast.
- Deleting sidecars from the UI. Stale fog/walls files are cleaned up manually in `.dm-screen/fog/` and `.dm-screen/walls/`.
- Undo history inside the modal. Strokes and wall edits are destructive; Reveal All / Cover All are the fog recovery tools.
- Per-map opacity. `mapFogTvOpacity` is global.
